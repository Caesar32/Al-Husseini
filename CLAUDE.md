## Architecture and business rules
- Flow: route (`can:` middleware) -> FormRequest/inline validation -> thin controller -> service (interface bound in `*ServiceProvider`) -> Eloquent. No Policies/Events/Jobs/Actions. Money/stock writes: `DB::transaction` + `lockForUpdate`.
- Stock: only `StockLedgerInterface` (`StockLedgerService::move/setTo`, inside a transaction) writes `products.current_stock`; each change appends a `stock_movements` row. `tests/Architecture/StockWriterTest.php` enforces it (scans `app/` only). Sole exception: the non-production `DemoDataSeeder` (`DemoBusinessSimulator`) writes backdated bulk rows with a matching journal, because `move()` cannot backdate or take an unflushed source. `Supplier.current_balance` and `Customer.current_credit_balance` are still written directly by several services, with no journal: find every writer before changing one.
- Payroll (owner decisions 2026-11-05, details in `docs/ai/hr.md`): nothing before `hire_date` counts; a hire inside the month gets the working days left with basic and allowances scaled to them; an absence day = basic / `monthly_working_days`, and absence alone never exceeds the basic or creates debt. Overtime still uses basic / calendar days, late penalties basic / 30.
- Scrap: on a full return the customer gets back the money actually paid and the trade-in battery stays in scrap stock. A factory sale takes ticked rows, the whole stock or the oldest N; the server picks and locks them (`ScrapBatteryService`).
- Blade: a page module (`Admin.page.register`) loads from `@section('script')`, after the layout's `core.js`. Inside `@section('content')` it dies with `Admin is not defined` and the page silently stops responding. `tests/Architecture/FrontendHygieneTest` budgets are ratchets: never raise them.
- Oil by the liter: `products.package_size` marks a liter product sold from sealed packages (stock, prices and cost are per liter). A piece product converts only through `ProductService::convertToLiters` (product form, or `products:convert-oils-to-liters`, dry run by default), never in bulk by category: the oils category also holds filters and pumps. `stock_factor` on invoice and purchase lines keeps old lines in packages, so any code moving stock from a document line must use `stockMilli()`.
- Money: 2-decimal values, compared in piasters (POS payments exactly == amount due; `finance.epsilon` for the rest). Invoice statuses live in `App\Enums\InvoiceStatus` (+ countable scope); `partially_refunded` counts net of `refunded_amount`.
- Numbers come from `DocumentNumberService` (invoices `INV-Ymd-000001`, claims `CLM-YYYYMM-n`, scrap batches). POS sales are idempotent via `idempotency_key` (scoped to the cashier).
- Returns are tracked per invoice line (`returned_quantity`). Supplier ledger is a running-balance chain (purchase posts full amount, then payment). Payroll consistency: `PayrollService::evaluateConsistency()` (includes overtime).
- `InvoiceObserver` / `PurchaseInvoiceObserver` are dead: never register them (double-posting). Invoices are created `withoutEvents`.
- Settings (`Setting::get/number`) are wired for working days/hours, overtime multiplier, warranty default months, invoice prefix. `vat_percentage`, `session_timeout_minutes`, `scrap_prefix` are NOT wired (owner decision). `allow_negative_stock` (default off; owner request 2026-11-07, for selling before the physical count) lets only a POS sale go below zero: `StockLedgerService::move(allowNegative:)` refuses any other decrease below zero, increases are always allowed, and `system:diagnose --audit` keeps failing its negative-stock check while one exists.

## Auth / permissions
- Guard `web`; `Gate::before` gives `super-admin` everything. Permissions are the catalogue in `PermissionRegistry` / `RolesAndPermissionsSeeder` (52). Roles: super-admin, branch-manager, accountant, cashier, workshop-supervisor.
- Backend: `can:<permission>` on every route + FormRequest `authorize()`. UI mirrors it (`@can` in sidebar, topbar, dashboard); never hide-only. `User::homeRouteName()` = landing page the user may open.
- Middleware: `EnsureUserIsActive`, `EnforceLockScreen`. Branch isolation: `BranchScope`/`BelongsToBranch` on 7 models (null branch or super-admin unrestricted; `BRANCH_ISOLATION=false` disables). Avatars live on the private disk. Manager override: only `finance.manager_override_hash|code`, fails closed.
- Env: `MANAGER_OVERRIDE_CODE_HASH` (required for overrides), `SEED_DEFAULT_PASSWORD`, `LOGIN_ACCOUNT_SWITCHER`, `LOGIN_SWITCHER_PASSWORD` (non-production only), `BRANCH_ISOLATION`, `FINANCE_EPSILON`.
